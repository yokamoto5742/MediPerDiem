# 再実行時の注意点

同じ月の収益データをもう一度追加した場合と、配信先マスタに医師を追加して再実行した場合の動作と注意点をまとめる。

## 同じ月の収益データを再度追加した場合

例: `医師別収益データ202608.xlsx` を2回実行した場合。

重複して追記されることはなく、変化表の対象月の列が上書きされる。警告や確認ダイアログは出ず、通常どおり完了メッセージが表示される。

| 処理 | 2回目の動作 |
| --- | --- |
| 対象月の判定 | ファイル名末尾の `YYYYMM` を対象月にする。ファイルの中身は見ない |
| バックアップ | 更新前の変化表を毎回バックアップする。設定の世代数を超えた古いものは削除される |
| 列の特定 | 見出し行に対象月の列が既にあるので再利用する。列は増えない |
| 値の書き込み | 「外来日当円」「外来収益合計」の両シートで、対象月の列の全医師行を今回の値で上書きする |
| 医師行の追加 | 1回目で追加した医師は登録済みのため再挿入されず、「変化表に追加した行」の通知も出ない |
| 後続の出力 | 配信用CSV、平均ブック、メール差し込みCSV、医局KPIメール差し込みCSVを作り直す |

同じファイルを2回実行しても結果は1回目と同じになる。修正版のファイルを同じ月で再実行すれば差し替えになる。

### 注意点

- **今回の入力に無い医師は空欄になる**: 対象月の列は全医師行を書き直すため、今回の収益データに載っていない医師のセルは空欄になり、前回の値は残らない。
- **ファイル名の年月を間違えると別の月として扱われる**: 中身が同じでも、ファイル名の年月の列が新規追加または上書きされる。
- **見出しが文字列だと列が増える**: 月の一致は数値(例: `202608`)との比較で行う。変化表の見出しが手入力で文字列の `"202608"` になっていると一致せず、末尾に新しい列が追加される。アプリが書き込んだ見出しは数値なので問題ない。
- **再実行を繰り返すと古いバックアップが消える**: バックアップは実行のたびに1世代増えるため、再実行を繰り返すと、最初の追加より前の状態のバックアップが世代数の上限で削除される。

## 配信先マスタに医師を追加して再実行した場合

配信先マスタは実行のたびに読み直し、出力ファイルはすべて作り直すため、追加した医師の分も反映される。ただし、その医師のIDの行が変化表(「外来日当円」シート)にあることが条件になる。

- **反映される出力**: 配信用CSV、平均ブック、メール差し込みCSV、医局KPIメール差し込みCSVの4つ。
- **過去の月も出力される**: 追加した医師の行には、変化表にある全ての月の値が出力される。
- **並び順**: 配信先マスタの記載順になる。
- **変化表は変わらない**: 変化表に行が追加されるのは収益データに載っている医師だけで、配信先マスタは影響しない。

### 注意点

- **変化表にIDが無い医師は出力されない**: エラーにはならず、どの出力にも含まれない。画面の結果欄とログに「【警告】宛先マスタのIDが変化表に無いためCSVに出力していません」と出るだけで、完了ダイアログには表示されないため、結果欄を確認する。
- **平均と合計が過去の月も含めて変わる**: 平均ブックの合計・平均と医局KPIメールの平均は、配信先マスタに載っている医師だけで計算する。医師を追加すると、過去の月の値も変わる。
- **再実行には収益データの選択が必要**: 出力だけを作り直す機能は無い。前回と同じ収益データを選べば、その月の列が同じ値で上書きされるだけで済む。
